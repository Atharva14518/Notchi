# Notchi onboarding and settings: manual checks

Use the Release app from a stable location. For login testing, copy it to Applications, quit other builds, launch that copy, and use the same copy for Accessibility approval. Rebuilding or moving an ad-hoc signed app can invalidate macOS permission identity. No permissions are granted automatically.

1. **First launch:** verify the seven scrollable tour chapters, progress-bar navigation, Back/Continue, and persistent footer. Complete or Skip tour, relaunch, and verify onboarding stays closed. Replay setup should start at Welcome without resetting preferences.
2. **Permission skip:** Continue without Accessibility. Hover and system-drag opening should work while Hover is on. Menu bar and global shortcut should also open the shelf. WhatsApp automation must remain gated on confirmed trust.
3. **Permission request and denial:** Open Settings in the permission guide should prompt for the intended build and deep-link to Accessibility. Dismiss/deny the prompt; the guide must remain usable with Continue, Check now and exact-path recovery steps.
4. **Permission grant:** enable the exact displayed app yourself. On return, the fresh query should confirm access within one second, celebrate, and advance. Entering the guide when already trusted must leave it available to read. Mouse-only hover does not require AX trust.
5. **Stale local approval:** if the switch is on but access is unconfirmed, follow the visible guide: Show app/Copy app path, remove obsolete entries, and add the exact final build. Quit/reopen if macOS requires it. No automatic TCC reset or self-grant occurs. Newer macOS may call the pane Device Control and Data Access.
6. **Revocation:** revoke access yourself while idle. Within one second WhatsApp should show unconfirmed access and stop automation, while hover keeps working. Verify the independent Hover setting is unchanged. Grant/revoke tests should not send private files.
7. **Tour:** watch more than one loop: the real file card enters, the conversion chip/progress ring/checkmark appear, and the card moves toward the Send tile while the mascot reacts. Go Back/Continue repeatedly; there should be no duplicated timers, overlapping text, or changes to the actual shelf.
8. **Login launch:** on Done or General, enable Launch at login. If macOS requires approval, follow Open Login Items and approve it yourself. The toggle must reflect actual SMAppService status, including pending approval and errors. Log out/in to verify exactly one menu-bar instance starts, without onboarding or a Dock icon. Disable and repeat to verify it no longer starts.
9. **Global shortcut:** record a new ⌘/⌃/⌥ combination; press it with Finder or another app active. The shelf should open and pin on the chosen display. Record the current combination again; it should still work. Also try a modified arrow key. Escape should cancel recording and restore the old binding. Switching apps or closing the window during recording should also cancel. Clear/Delete should disable it. Plain letters and conflicting system/app bindings should show an error without losing the previous valid shortcut. Relaunch and repeat. CUA-injected keystrokes may bypass WindowServer's Carbon hotkey dispatch; verify with physical keys.
10. **General layout:** try Precise, Balanced, Relaxed and compare dwell time/hot zone. Try Compact, Standard, Roomy, both empty and with cards/Send. On multiple displays test Follow cursor, Main display, a named external display, unplugging/replugging the chosen display, and a display to the left/above the main screen. Disconnected choices should fall back to main. A native share/save UI must keep its anchor until dismissed.
11. **Shelf persistence:** add disposable test files, quit/relaunch with Keep shelf enabled, and verify cards restore. Disable it and verify current cards remain, then quit/relaunch: no cards restore. Re-enable it and add a card; subsequent launches should restore it. Original files must remain on disk in every case.
12. **Shelf expiration:** use disposable fixture records whose added dates are older/newer than the chosen custom cutoff (for example, 13 days). Verify old cards and offline bookmark references expire at startup, when changing the cutoff, or during the minute-based sweep. Recent cards remain. Never should an original file be deleted. Enter any interval from 1–3650 days. Check invalid/out-of-range input is clamped, then turn Auto-clear off to disable expiration.
13. **Save folder:** choose a default folder in Shelf settings. Send → Save to… should start there. Save a test copy and compare its contents; the source must remain. Relaunch and verify the bookmarked location remains. Reset should restore Ask each time. Disconnect/unmount the folder and confirm an unavailable-folder message, then choose another folder.
14. **Action defaults:** set Tiny/Best and JPG/PNG, open fresh compression/conversion sheets, and verify their initial selections. Override a sheet and verify its action uses that choice. Under Keep both cards, source/result should both remain; under Replace source card, only successful accepted outputs replace the source card. A failed action must leave its source card. In both modes the original file on disk must remain intact.
15. **Reduced Motion:** enable macOS Accessibility → Display → Reduce motion yourself. Replay onboarding and change Settings sections. Transitions should use short fades, with no mascot hops/waves, looping tour movement, chip springs or tile wiggles. The tour remains a readable static three-step preview. Change the setting while a screen is open and verify it reacts.
16. **Settings and About:** menu bar Settings… and ⌘, should open the same SwiftUI Settings scene. Navigate all five requested sections and Credits, close/reopen, and confirm saved values survive relaunch. About should show bundle version/build, a clear update placeholder, a working local README link and macOS support link. Replay should reopen onboarding. No extra Dock icon or second settings design should appear.
17. **Existing behavior:** test a multi-file Finder drop, conversion, ZIP, Send → More cancellation, Save cancellation, and pin/unpin after onboarding. Check full-screen apps, Mission Control, Stage Manager, screen hot-plug and sleep/wake. With Hover off, the menu bar/global shortcut should still open the shelf.

Automated checks cover settings persistence, reference-only expiration/opt-out, source-card replacement safety, permission grant/revocation refresh, sensitivity timing, panel geometry, shortcut parsing, save-folder bookmarks, older-schema preference migration and custom retention bounds, alongside the existing action/drop/share suite. They do not grant TCC access, log out, or send files to recipients.


## Scanning and OCR

1. **Open and retain a draft:** open the notch, click Scan, choose two shelf images or image/PDF files. Close with the header x and reopen Scan: the pages should remain. Quit/relaunch: the unsaved scan draft should be gone; original files should remain.
2. **Continuity Camera:** with an eligible nearby iPhone/iPad on the same Apple Account, Wi-Fi/Bluetooth enabled, click Import from iPhone… and choose Scan Documents. Scan multiple pages, accept on the phone, and verify all arrive in Notchi. Cancel on the phone and check the source UI remains usable. With no eligible device, the menu should remain a harmless help/fallback entry; choose shelf/files instead. This requires real hardware and is not automated.
3. **Screen capture:** explicitly choose Capture selected area. Verify the permission prompt on first use, deny it and check the friendly guidance, then grant Screen Recording in Settings and retry (relaunch if macOS requests it). The overlay should disappear before selecting a region and return afterward. Escape should cancel without creating a page/card or leaving the panel hidden. The capture must contain only the selected region.
4. **Edges and lighting:** use a tilted page on a contrasting table. Verify violet sweep, edge outline, perspective flattening and readable result. Try an image with no distinct document: keep the full image with a visible warning. Try a very dark photo: show the lighting message and preserve existing draft pages.
5. **Looks and ordering:** change Color → Grayscale → B&W. Drag the second thumbnail ahead of the first, select each to verify identity, remove one and add another. Create PDF and open it in Preview: page order/look must match. Cancel a drag outside the panel; a later external text drop must not reorder pages.
6. **Searchable export:** export once with Searchable text layer on and once off. In Preview, search/copy a known sentence from the first PDF; the second should be image-only. Check page images remain visually identical without visible duplicate text. The new PDF card should pop onto the shelf, be tagged New and drag out as a PDF. Save exported files if you need to retain them beyond temporary storage.
7. **OCR:** choose read text on an English image, Hindi image and a multi-page scanned/rotated PDF. Verify text boxes align, lines appear in a stagger, reading glasses show and Copy text includes nonempty pages. Compare against the source for recognition errors. On a runtime without Hindi support, a clear language notice must appear. Blank/locked/unreadable files should produce friendly errors without a stuck progress state.
8. **QR/barcodes:** choose QR / barcode on a fixture. Check the payload, Copy code and explicitly click Open link for a trusted test URL. No link should open before that click. Non-web payloads must not show an Open link action. Try an image without codes and check the friendly message.
9. **Cancel/interruption:** cancel during import, look conversion and searchable export, close/reopen the scanner, then run a fresh job. Existing pages must remain, cancelled results must not appear later, and Cancel/progress must reset. Check Reduce Motion removes scan sweeping/perspective movement and text stagger. Check screen hot-plug, full screen, Mission Control and sleep/wake while a draft is open.
10. **Bounds and permissions:** try a PDF over 20 pages, then a normal one. Verify the 20-page guidance, preserved draft, and successful retry. Only an explicitly requested screen capture should ask for Screen Recording; OCR/file import must not prompt for camera/microphone or Accessibility permissions.

Scanner export regression: while searchable export runs, verify page X of Y and percentage update. If native OCR does not finish within 45 seconds for a request, the spinner must stop with a helpful error; all draft pages must remain. Uncheck Searchable text layer and retry: an image-only PDF should be created without another OCR request. Cancel must immediately re-enable controls even when native OCR is slow to stop.


## Document sharing regression

1. Forward a valid PDF, choose WhatsApp → Copy & open. It should launch without an unsupported-file alert from opening the PDF. Notchi should show Ready for WhatsApp and not claim Sent. Choose a test chat yourself, use Attach → Document and choose the prepared PDF using Show files or Copy location + ⌘⇧G. Check its name, page count and contents before sending. No message is sent automatically.
2. Repeat with TXT, DOCX, image, video, audio, ZIP and an unfamiliar extension, within the destination’s limits. Paste/drag support varies by app; Attach → Document is the fallback. Try Telegram if installed and another native sharing service. The destination still controls formats, size limits, accounts and delivery.
3. Forward multiple files with duplicate names: verify all prepared attachments have distinct names with their extensions preserved. Forward a folder: verify its ZIP contains nested files. Make a ZIP should package the current selection into one attachment, leaving source files unchanged.
4. Close/reopen Notchi after preparing files but before attaching: the copies should still exist for the destination to read. Copy writes file URLs. Copy location intentionally writes the folder path; Copy & open restores the file URLs. Check the original files remain if a destination consumes or moves its copy.
5. Use disposable sparse fixtures for oversized-file checks: WhatsApp should report its document size limit without launching it or claiming success. A missing/unreadable source should return a friendly error and keep Send usable. Cancelling a native share should not report Sent. Test launch failure with a test double; prepared files must remain available through Show files.


## WhatsApp recipient-picker automation

1. With a trusted, stable Notchi build and WhatsApp unlocked, open any chat once. Forward a harmless fixture PDF from Notchi → WhatsApp. The notch should get out of the way, the File picker should select only the prepared attachment copies, and WhatsApp’s native recipient list should open. All preselected recipients must be cleared; Send should be absent/disabled until you select a recipient yourself. Cancel this verification instead of sending.
2. Repeat with multiple files, Unicode/duplicate names, a ZIP folder and different Finder file-picker view modes. Verify the correct attachments in WhatsApp’s preview. Choose a recipient and explicitly send a disposable fixture yourself if desired. Notchi must never press Send or display a fabricated Sent confirmation for automation.
3. Deny/revoke Accessibility: show Permission help with Open Settings, Check now and exact-app instructions, preserve files and never manipulate WhatsApp. Grant the exact current build and retry. Changing an ad-hoc signature can invalidate an old TCC approval; use a stable development signing identity for repeated builds.
4. Test WhatsApp closed, already running, minimized, locked, with no selected chat, and with an existing attachment/file picker. Existing drafts must not be overwritten. Switch to another app mid-preparation: automation must stop before entering keys or choosing files in another app. Retry after cancelling any native draft.
5. Open Notchi from its menu/hotkey during preparation, or lock/sleep the Mac. Automation must cancel without continuing later. On a WhatsApp update that changes identifiers, show a bounded error with manual recovery; never guess coordinates or activate a Send control.


## UI polish checks

1. Open every Settings tab. The sidebar stays 200 pt wide; Credits and all labels remain on one line. Toggle and segmented surfaces use the theme, and four-or-more options use the custom dropdown. Info popovers contain at most 12 words.
2. Tab through buttons and activate with Space/Return. Focus must be lime, never the default blue halo. Disabled controls must ignore activation and show 40% opacity. Verify mouse press/release and scroll cancellation on app tiles.
3. Check the empty shelf, action options, trim, scan looks and setup. There should be no stock grey toggles, segmented pickers, dropdowns, text fields or sliders in app-owned UI. System dialogs remain native.
4. Open Send with a long filename and multiple files. Check truncated names, complete sizes, number-only count, one primary Send button and three utility icons. Attention messages stay short; full details are in help/accessibility text.
5. Enable Reduce Motion manually and revisit the controls. There should be no press scaling, sliding segment highlight, switch squash, mascot hop or tile wiggle; short fades remain.
