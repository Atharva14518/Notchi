# Get a link

Select a shelf card and tap **Get link**. Choose 1 hour, 24 hours or 7 days. Passwords and download limits are optional. Folders are zipped. Once R2 accepts the file and the backend publishes its record, the paper plane flies, a link chip lands, and the link is copied automatically. Original files remain unchanged.

**My links** is available from the panel's link icon and Settings → Links. It shows expiry countdowns and Copy/Revoke controls. Expired links are unavailable immediately; file/record cleanup follows the scheduled backend job. Download limits use one-use signed tickets; replaying a ticket does not grant another download. Already downloaded copies or started streams cannot be recalled.

## Local setup first

The backend lives in `Backend/`. See its README for all environment variables, Supabase migration and configuration. No cloud resources or paid services were created/deployed in this pass.

1. Start Docker Desktop, then from `Backend/` run `npm ci`, `npm run setup:local`, `npx supabase start`, and `npx supabase migration up` (local by default).
2. Run `npm run connect:local` to load the local project keys into the ignored `.dev.vars` without printing them. Random application secrets are generated by the setup script.
3. Run `npm run dev:local`; restart it if credentials changed while it was running. Open a **Debug** Mac build and set `http://127.0.0.1:8787` in Settings → Links. Release builds require HTTPS.
4. Sign in by email; use the local inbox at port 54324 to open the magic link. Production email and Apple sign-in need their Supabase/provider configuration. Real Apple sign-in requires an Apple Developer Services ID and provider credentials; local mode does not fake it.

## Client files

- `LinkModels.swift`: API records, expiry/countdowns, pending uploads and safe error messages.
- `LinkConfiguration.swift`: service origin validation; loopback HTTP is Debug-only.
- `LinkKeychain.swift`: refresh credentials, PKCE verifiers and pending upload passwords in Keychain, scoped to the service origin.
- `LinkAuthStore.swift`: Apple web OAuth/email magic links, PKCE/state checks, access-token memory cache and refresh rotation.
- `LinkAPI.swift`: bounded JSON requests and sanitized errors; redirects are rejected.
- `BackgroundLinkUploader.swift`: file-backed background URLSession uploads with real byte progress and stable task UUIDs.
- `LinkUploadStore.swift`: owned staging copies/ZIPs and an atomic recovery journal with no signed URLs or plaintext secrets.
- `LinkCoordinator.swift`: upload/publish/retry/cancel, reattachment, clipboard and My links.
- `LinkViews.swift`: themed expiry/password/download-limit flow and Links settings.
- `LinkFlight.swift`: paper-plane animation; the mascot's thumbs-up uses the shared animation presets. Reduce Motion uses fades.

## Xcode configuration

The generated project includes `Links/` and the guide automatically. A `notchi` URL scheme in Info.plist handles PKCE callbacks. `NSAllowsLocalNetworking` supports the local developer workflow; the client separately forbids non-HTTPS non-loopback origins, and Release forbids HTTP. No native Sign in with Apple entitlement is required for this web OAuth flow. Configure a stable signing Team/certificate for consistent Keychain access across builds. Keep a single running/registered copy for callback testing. The current unsandboxed agent needs no added network entitlement; review outgoing networking and Keychain access if enabling App Sandbox later.

Background file uploads are managed by macOS, with `sessionSendsLaunchEvents` enabled. Uploaded-but-unpublished jobs retry completion after a relaunch. Forced termination, sleep, network loss or expired upload capabilities can interrupt a transfer; Retry reissues a pending PUT capability, while Cancel releases the reservation. Nothing is labelled successful until the completion API returns a real share record. Keychain failures and offline/auth failures leave retryable state.

## Manual tests

1. Upload a small image/PDF at each expiry; verify a real progress percentage, automatic clipboard copy, one Link copied toast and a spring/fade result chip.
2. Try a folder; verify the downloaded ZIP contains its files and the original folder stays intact.
3. Set a password; a wrong password must fail, the correct password must allow download.
4. Set one download; double-click/replay the signed ticket and verify only one accepted download request. Try concurrent requests.
5. Create five free links; the sixth must be refused. Revoke one, then create another. Test exactly 100,000,000 bytes and one byte larger.
6. View My links, verify countdowns, Copy, Revoke and Refresh. The revoked public page must be unavailable.
7. Pause networking and cancel/retry; no late callback may copy a cancelled link or reset a newer job.
8. Quit/relaunch during transfer and during finalization. Verify background task reattachment or a clear retry state, and no duplicate share.
9. Sign out/change service while idle; credentials and old account links must disappear. Old refresh callbacks must not sign you back in.
10. Use a file name containing HTML punctuation; the page must show plain text. Test blocked executable/script types.
11. Enable Reduce Motion; the flight becomes a fade and controls remain usable with keyboard focus.
12. Verify no application logs contain file bytes, credentials, filenames, signed URLs or share URLs. Framework/provider diagnostics are controlled separately.
